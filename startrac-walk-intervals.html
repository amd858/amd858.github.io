StarTrac Walk Intervals

Arduino Uno/Nano · HIIT interval controller · relay speed control · non-blocking state machines

Arduino firmware that turns a StarTrac treadmill into a self-driving HIIT walking-desk controller. The system physically presses the treadmill's +/− buttons via relays to ramp speed up and down, drives a vibration motor to fake pedometer step counts, and runs a full high/rest interval scheduler with live countdown display. No modification to the treadmill itself—the controller sits between an external button panel and the treadmill's control board, driven entirely from a single ATmega-class MCU with a non-blocking main loop.

Core Features

Speed Control via Virtual Button Presses

The treadmill's stock +/− buttons are driven through relay/optocoupler outputs. Speed ramping uses a two-phase strategy: up to 3 single "jump" presses for fine adjustments, then batched long-presses that hold the button through a run of steps, computed to land on safe checkpoint speeds. Every intermediate speed is streamed out over SoftwareSerial for external logging.

HIIT Interval Engine

A state machine alternates between HIIT_REST (recovery pace) and HIIT_HIGH (interval pace) phases on configurable duration tables. A 10ms tick counter drives the countdown, which is displayed live on the TM1637 4-digit display. Speed automatically ramps at each transition without user input.

Fake Step Injection

A second state machine pulses the linear/vibration motor to simulate footfalls for an attached pedometer, timed to the belt's real cadence. Step injection automatically pauses during rest and high-intensity phases so step counts stay realistic and don't double-count during active intervals.

Extreme Mode / Live Overrides

A debounced extreme-mode button lets you cycle interval duration presets or bump the interval speed tier on the fly, mid-session, without stopping the belt. This makes it possible to adjust workout intensity without interruption.

Adaptive Rest Extension

A dedicated wait button extends the rest phase in real time if you're not yet back in position. The ready LED signals when it's safe to end the rest early, so the next high-intensity phase never starts before you're ready.

Fully Non-Blocking I/O

All physical buttons (start/stop, extreme mode, wait) are handled through explicit debounce state machines. The main loop runs at 10ms ticks with no blocking delay() calls in the treadmill or step state machines—only the low-level virtual button press helpers use bounded delays to match real relay actuation timing.

Treadmill State Machine

Behavior is driven by treadmill_state, transitioning only on debounced button edges:

StateTriggerBehavior
STOPInitial stateIdle; belt off, display shows the next interval duration.
BOUNCING_BEFORE_CONSTANT_SPEEDStart button pressedDebounce gate; blocks transition noise.
CONSTANT_SPEEDDebounce elapsesBelt ramps to the first constant-speed tier; step counting and speed cycling active via the extreme button.
BOUNCING_BEFORE_HIIT_RESTStart pressed againDebounce gate.
HIIT_RESTDebounce elapsesBelt drops to recovery pace; countdown displayed; ready LED signals when it's safe to end the rest early.
HIIT_HIGHRest countdown elapsesBelt ramps to the current interval speed tier; countdown displayed; step injection paused.
BOUNCING_BEFORE_STOPStop pressedDebounce gate; clears back to STOP.

Speed Tables and Configuration

Constant Speed Tier (Walking Mode)

const int CONSTANT_SPEEDS_ARRAY[5] = { 25, 32, 40, 80, 100 };
// Mapped to: 2.5, 3.2, 4.0, 8.0, 10.0 km/h

HIIT High-Intensity Speeds

const int HIIT_HIGH_SPEEDS_ARRAY[8] = { 54, 80, 90, 100, 110, 120, 130, 140 };
// Mapped to: 5.4, 8.0, 9.0, 10.0, 11.0, 12.0, 13.0, 14.0 km/h

Interval Duration Tables (seconds)

const int HIIT_high_interval_array[10] = { 60, 30, 150, 240, 300, 360, 420, 480, 540, 600 };
const int HIIT_rest_interval_array[4] = { 60, 64, 120, 180 };
// Extreme mode button cycles through these presets

Virtual Button Press Timing

int on_time = 120;      // Button press hold duration (ms)
int off_time = 190;     // Button release duration (ms)
// Tune these to match your treadmill's responsiveness

Motor Step Injection Timing

#define SLOW_STEP_TICKS  88     // Motor on/off ticks at recovery pace
#define FAST_STEP_TICKS  53     // Motor on/off ticks at walking pace
// Lower = faster motor pulses (higher cadence)

DIP Switch Configuration

Three bits (A1, A2, A3) allow 8 different configuration profiles (binary 0−7). Currently used for selecting preset profiles; expand as needed for future tuning parameters.

Software Architecture: Core State Machines

1. Speed Ramping (set_treadmill_speed, jump_up_*, jump_down_*)

Purpose: Moves the treadmill from one speed to another using only the stock +/− buttons.

Mechanism: Up to 3 single "jump" presses first, then switches to batched long-presses. The next_odd_ten helper computes checkpoint speeds to prevent overshooting.

Output: Streams every intermediate speed out over SoftwareSerial at 115200 baud for telemetry.

2. Interval Scheduling (treadmillProcessing)

Purpose: Owns the top-level treadmill_state machine and interval countdown.

Mechanism: Uses a 10ms tick counter against duration tables to time each phase. Calls set_treadmill_speed at every transition. Drives the TM1637 countdown display and the activity flag.

Output: Updates today_total_steps, activity_flag, and display buffer.

3. Fake Step Injection (fakeStepsProcessing)

Purpose: Pulses the motor to simulate footfalls for a pedometer.

Mechanism: A 5-state machine (MOTOR_STOP, MOTOR_ACTIVE, IDLE, PAUSE_STEPS, PAUSED) fires the motor for a fixed on/off tick window per step. Automatically pauses whenever the treadmill enters a HIIT phase or extreme-mode multiplier is active, so injected steps never overlap high-intensity intervals.

Optimization: Step counts remain valid across pause/resume cycles.

4. Extreme Mode Button (extreme_mode_button_processing)

Purpose: Let the user cycle speed tiers or interval-duration presets mid-run.

Mechanism: A debounced press/release state machine that either advances extreme_speed_multiplier (and immediately calls set_treadmill_speed) or advances interval_index into the duration tables, depending on the current treadmill state.

5. Adaptive Rest Extension (aditional_wait_calculator)

Purpose: Give extra recovery time if the user presses the wait button before rest phase ends.

Mechanism: Lights the ready LED inside the last ~7 seconds of rest. If the wait button is held in the final ~5 seconds, extends the rest phase by one tick per loop pass, compounding across calls.

6. Display Formatting (displayTime, print_countdown)

Purpose: Render remaining interval time and current speed tier on the 4-digit TM1637 module.

Mechanism: displayTime packs mm:ss into the display's colon format. print_countdown compresses long countdowns (>90s) into a coarser step so the display doesn't update every second, and shows the active speed tier digit alongside the time.

Telemetry and Monitoring

SoftwareSerial Output

Connect A0 (TX) to a serial monitor at 115200 baud to observe live telemetry:

  • Every speed ramp: intermediate speed values as they're reached
  • Treadmill state transitions: STOP, CONSTANT_SPEED, HIIT_REST, HIIT_HIGH
  • Step counter updates and motor state changes
  • Button press events and debounce transitions

Display Output (TM1637)

Four 7-segment digits showing:

  • During constant speed: Speed tier (0−4) on the rightmost digit
  • During HIIT: Countdown mm:ss with colon indicator
  • When stopped: Next interval duration preview

Deployment and Installation

Prerequisites

  • Arduino IDE 2.x or PlatformIO
  • TM1637Display library (Avishay Orpaz) — install via Library Manager
  • SoftwareSerial — ships with standard AVR core, no extra install needed

Configuration Steps

  1. Review the pin map against your wiring. Adjust relay GPIO assignments if your board layout differs.
  2. Tune on_time and off_time: Start at 120ms/190ms and increase if the treadmill misses button presses, or decrease if it over-responds.
  3. Adjust speed tables: Edit CONSTANT_SPEEDS_ARRAY and HIIT_HIGH_SPEEDS_ARRAY to match your target speeds and the treadmill's acceleration curve.
  4. Set interval durations: Edit HIIT_high_interval_array and HIIT_rest_interval_array to your preferred workout schedule.
  5. Configure step injection: Adjust SLOW_STEP_TICKS and FAST_STEP_TICKS to match your motor's responsiveness and target cadence.

Flashing and Testing

  1. Select your Arduino Uno or Nano board and COM port in the IDE.
  2. Upload the sketch.
  3. Open the Serial Monitor (115200 baud) to watch telemetry during testing.
  4. Test each button in isolation (start, stop, extreme mode, wait) before running a full interval session.
  5. Verify that speed ramps smoothly and the display updates correctly.
  6. Monitor step injection by pressing the extreme button and observing motor pulses.

Safety Checks

  • Confirm the treadmill's emergency stop is always wired and accessible, independent of the controller.
  • Test the stop button thoroughly — it should cut the belt immediately via the TREADMILL_STOP relay.
  • Verify the relay outputs are wired correctly to avoid any possibility of simultaneous button presses (which could jam the treadmill).
  • Start with slow speed tiers and gradual intervals during your first session, then increase intensity once you're confident in the system's response.

Wireless Fan Control (ESP-NOW)

The project includes optional ESP8266-based wireless fan control via ESP-NOW:

  • Master: Monitors the cooling-fan trigger pin and sends the state over ESP-NOW (no WiFi router needed).
  • Slave: Receives the signal and drives a physical fan relay.

This allows the treadmill controller to trigger cooling without wired connections, useful if the fan is mounted remotely or you need isolation between the treadmill circuits.
